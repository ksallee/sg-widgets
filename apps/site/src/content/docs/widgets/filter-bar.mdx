A row of facet pills. Each lists one field's values with a count and ticking them adds a condition to
the bound tree. A More filters pill opens the same tree in the full editor.

## Install

```sh
pnpm dlx shadcn@latest add https://sg-widgets.dev/r/react/filter-bar.json
pnpm dlx shadcn-svelte@latest add https://sg-widgets.dev/r/svelte/filter-bar.json
```

<Demo name="filter-bar" title="FilterBar: status, sequence and shot type over Shot" />

An untouched facet is a quiet dashed pill naming its field. Ticking a value turns it into a pill
reading the field and the values ticked, with a count once there are several, and opening the pill
again reopens the checklist. A control at the end of the pill removes it, and once any pill is
active a Clear all control drops every condition the pills contribute, leaving anything built in
the dialog alone. Other operators on a facet field, is none of and is empty among them, are set in
the dialog; a pill holding one reads its condition as text.

## Props

| prop | type | default | meaning |
|---|---|---|---|
| `entityType` | `string` | required | Type the pills and the counts read on. |
| `client` | `SgClient` | required | Reads the schema and the rows the counts are tallied from. |
| `schema` | `SchemaService` | one built from `client` | Share one across a page. |
| `facets` | `string[]` | required | Field names to offer as pills, in order. |
| `value` | `FilterGroup` | `emptyFilter()` | The tree the pills write into. Two-way in Svelte through `bind:value`. |
| `counts` | `(field, filters) => Promise<Record<string, number>>` | — | Counts per value for one facet. Wire it to a `_summarize` grouping call. |
| `sampleSize` | `number` | `200` | Rows read for the tally when `counts` is not given. |
| `hidePaths` | `string[]` | `[]` | Passed through to the dialog. |
| `disabled` | `boolean` | `false` | Blocks every pill. |
| `size` | `'sm' \| 'md' \| 'lg'` | `'md'` | Pill heights 8, 9 and 10. |
| `class` / `className` | `string` | — | Merged after the widget's own classes. |

Every other attribute is spread onto the root: `id`, `aria-*`, `data-*`, key handlers and a
`ref` to the root element.

## Events

| event | payload | when |
|---|---|---|
| `onChange` | `FilterGroup` | The tree changed, on every tick and on Apply in the dialog. Svelte also binds it with `bind:value`. |

## Slots

None. The dialog behind More filters takes the editor's slots.

## Keyboard

| key | does |
|---|---|
| `Tab` | Moves from pill to pill, and to a pill's remove control. |
| `Enter`, `Space` | Opens the value list under the cursor. |
| `Arrow` keys | Move the cursor in the open list. |
| `Enter` | Ticks and unticks the value under the cursor. |
| `Escape` | Closes the open list. |

## API behaviour

`POST /entity/<type>/_summarize` answers one group per distinct value with a count, and its
`group_value` is the raw value while `group_name` is the server's rendering, which is not unique on
an entity field (020_summarize). Pass `counts` to use it. Without it the bar reads one page of rows
and tallies them, so a value outside that page is missing and the numbers are counts of what was
read.

Counts are taken against the tree with every facet's own conditions stripped, so ticking one value
does not empty its neighbours.

A status or list value is the raw code, never the display label, and a code outside `valid_values`
matches nothing rather than erroring (field_types/status_list). An entity value is a `{type, id}`
hash (field_types/entity).

Every negating operator, `not_in` included, also matches rows where the field is unset
(017_filter_operators), so is none of on a facet returns the blanks as well.

## Reference

The dashed add-a-filter pill and the value checklist follow ReUI's Filters 2.5.2, and the counts beside each value follow shadcn's data table faceted filter. Neither is installed.
