title: Install
description: How a host app installs the widgets, and the two things it has to do by hand.
---

One command installs every item of a registry.

```sh
pnpm dlx shadcn@latest add https://sg-widgets.dev/r/react/sg-widgets.json
pnpm dlx shadcn-svelte@latest add https://sg-widgets.dev/r/svelte/sg-widgets.json
```

A widget page names its own item, for a host that wants one widget rather than the set.

Run `init` first. It writes `components.json`, the stylesheet and `lib/utils`, which every item
imports. A host that copies those three from somewhere else instead gets them without their
packages; the items name what `lib/utils` and the stylesheet need, so the CLI adds them either way,
but nothing generates `lib/utils` itself.

## The core package

`@sg-widgets/core` is not on npm yet. Every item names it as a dependency, and the CLI installs an
item's packages in one call, which fails on that name and installs none of the others: the files
land, `package.json` is left as it was, and `"latest"` is written over a `link:` spec already there.
Install the packages yourself afterwards, with core pointed at a local checkout.

```sh
pnpm add @sg-widgets/core@link:../sg-widgets/packages/core \
  bits-ui @lucide/svelte @internationalized/date \
  @tanstack/svelte-table @tanstack/virtual-core \
  clsx tailwind-merge tailwind-variants tw-animate-css
```

```sh
pnpm add @sg-widgets/core@link:../sg-widgets/packages/core \
  @base-ui/react lucide-react \
  @tanstack/react-table @tanstack/react-virtual \
  cn react-day-picker date-fns tw-animate-css
```

Each line is what the items name plus what the shadcn primitives they install name, for the whole
registry. A host installing one widget needs less.

The `link:` line is put back after each `add`. The widgets import core by its bare name and nothing
else in an item reaches into this repository, so a published package will drop straight in and the
CLI's own install will carry the rest.
